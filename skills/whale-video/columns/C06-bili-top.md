## 主形态：热榜 100 条，我一条条看

### 素材队列（可持续的根）

- 抓取：`/x/web-interface/ranking/v2?rid=0&type=all` → 落 `data/queue.json`（100 条）
- 字段：`bvid / title / author / view / danmaku / reply / fav / duration / pic / done`
- **每条做完标 `done: true`**，下期取第一条未做的
- 队列补货：每周重抓一次，把新进榜的补进队列尾部（不打断顺序）
- 产能：**100 期**；日更可用 3 个月，周更可用 2 年

### 每期固定结构（100–120 秒，台词 16–18 句）

> v3：**要真的边看边评**，不是念数据。引用片段必须播，但比例受控。

| 段 | 秒 | 内容 | 画面物料 |
|---|---|---|---|
| 1 | 0–6 | 报身份：「热榜第 N 条，播放 X 万」 | 封面 + 大数字 + 分区标签 |
| 2 | 6–16 | 这条是什么（说人话，一句钩子） | 标题卡 + 时长条 |
| 3 | 16–35 | **引用片段 1**（4–6s，原声）+ 我的第一反应 | 片段 + 弹幕流 |
| 4 | 35–55 | **引用片段 2**（4–6s）+ 一条高赞评论 | 片段 + 评论卡 |
| 5 | 55–75 | **引用片段 3**（4–6s）+ 数据对比 | 片段 + 条形图 |
| 6 | 75–95 | 三句吐槽：一句数据、一句梗、一句狠话 | 大字卡组 |
| 7 | 95–108 | 一句判词：这条教会我什么 | 纸卡 + 印章 |
| 8 | 108–120 | 下一条看谁 + 三连 | 官方图标 |

**台词密度**：100 秒 ≈ 330–380 字（16–18 句），平均每 6 秒一句；引用片段期间口播不停（压低原声）。

### 引用与侵权（必须遵守，写进流程）

**结论先说：能播，但「播多少」和「有没有自己的判断」决定风险；简介声明不能免责，只能降低被处理的概率。**

| 项 | 安全做法 | 红线 |
|---|---|---|
| 单段时长 | 3–6 秒 | >10 秒 |
| 全片引用总量 | ≤15 秒，且 ≤原片 5% | >原片 10% |
| 引用位置 | 选过程/细节，避开高潮与结局 | 连续播剧情 |
| 评论占比 | 口播时长 ≥ 引用时长 ×3 | 纯播放配字幕 |
| 画面标注 | 角标「引用 · BVxxxx」 | 抹掉来源 |
| 简介 | 「片段用于评论，版权归原作者，侵删」 | 只写声明不控制比例 |
| 原声 | 压低至 -18dB，盖上自己的口播 | 保留完整原声抢注意力 |


### 同行先例（B 站已有成熟赛道）

| 类型 | 案例 | 数据 |
|---|---|---|
| 锐评榜单 | 【锐评】音乐平台网络热歌榜 | 173 万播放 / 27 分钟 |
| Reaction | 科比看自己的 AI 整活视频 Reaction | 722 万播放 / 4:35 |
| 吐槽影视 | 《云边有个小卖部》爆笑吐槽 | 514 万播放 / 10:49 |
| 专业拆解 | 歌剧老师锐评春晚四首歌 | 98 万播放 / 40 分钟 |

共同点：**时长长（7–27 分钟）、口播密度高、片段只当论据、观点极其个人**。
这正是「合规」的样子：引用服务于评论，而不是评论服务于引用。


### 为什么「解说」风险高、「锐评」风险低

| 类型 | 是否讲完剧情 | 是否替代原作 | 风险 |
|---|---|---|---|
| 几分钟看完 / 影视解说 | 讲完（含结局） | 高（看完不用看原片） | **高** |
| 拉片 / 专业拆解 | 局部 | 低（看完更想去看） | 中低 |
| 锐评 / 吐槽 | 只讲一个点 | 低 | **低** |

- 国内已有判例：全国首例「图解电影」案，用 382 幅截图讲完《三生三世十里桃花》剧情，被判侵权赔偿（[国家版权局报道](https://www.ncac.gov.cn/xxfb/yjdt/201908/t20190816_49598.html)）。
- 关键不是「引用了几张画面」，而是**是否构成替代**：把剧情和结局讲完，观众不再需要看原作 = 损害原作市场。
- 这也是我们只做「锐评」不做「解说」的原因：**锐评不需要讲完剧情**，引用只为佐证一个观点。

> 平台侧还有一层：B 站与部分片方/版权方有合作授权池，授权内的二创才真正无风险；我们不在授权池里，所以按「比例 + 转换性」的保守标准执行。

### 五条防侵权操作（按顺序自查）

1. **转换性**：每一段引用都必须被「解释」，不能只是播放。
2. **比例**：单段 3–6 秒，全片 ≤15 秒，且 ≤原片 5%。
3. **不替代**：不播高潮、不播结局、不连播剧情，观众看完不会觉得「不用看原片了」。
4. **标注**：画面角标「引用 · BVxxxx」，简介写「片段用于评论，版权归原作者，联系即删」。
5. **原创占比**：口播时长 ≥ 引用时长 ×3，且有自己的数据/弹幕/评论佐证。

参考：[bilibili 社区公约](https://member.bilibili.com/studio/convention/content?index=3-1&navhide=1)、[主站视频二创计划服务协议](https://www.bilibili.com/blackboard/activity-xpWA0uj03W.html)、[二次创作视频的常见法律问题](http://m.gdshlawfirm.com/nd.jsp?id=263)

> ⚠️ 额外风险：本账号是 **AI 生成内容**，平台对 AI 二创的审查更严。同样比例下，AI 号被判搬运的概率高于真人号，所以**比例要再保守一档**（单段 3–4 秒，全片 ≤12 秒）。

三条硬规矩：
1. **每一段引用前后都必须有自己的判断**（前一句说「看这里」，后一句说「这说明」）。
2. **不能替代原作**：把原片最值钱的部分完整放出来 = 搬运，平台会判。
3. **不做合集**：一期只评一条，不拼多条原片。

技术实现：`catbus bilibili item media <BV>` 拿直链 → ffmpeg 截 3–6 秒 → Remotion `OffthreadVideo` 播放 → 原声 -18dB 混入。

### 版权边界（必须遵守）

- 封面：单次 ≤3 秒，且标 `来源：BVxxxx`
- 画面：**不播原片**，只用封面 + 弹幕图形 + 评论卡
- 台词只用它的标题与公开数据，不整段引用内容
- 出现即标「合理引用 · 非搬运」

### 为什么可持续

1. 素材自动产生（榜单每天变）
2. 选题不用开会（队列排队）
3. 结构可模板化（六段固定）
4. 能长期连载（100 期起）

## 1. 栏目定位

- **替观众做的事**：把平台上散落的数字，算成一个他想不到的结论。
- **观众承诺**：看完能记住一个数字，并且能拿去跟人聊。
- **时长**：40–120 秒（单条「之最」40–70 秒；多榜合一 90–120 秒）
- **节奏**：周更（数据每周抓一次，选题池现成）

## 2. 数据源（全部公开 API，无需登录）

| 用途 | 接口 | 关键字段 |
|---|---|---|
| 全站热榜 100 条 | `/x/web-interface/ranking/v2?rid=0&type=all` | view / danmaku / reply / favorite / coin / share / owner / title / pic |
| 分区热榜 | 同上，`rid=` 分区 id（如 1 动画、160 生活、188 科技） | 同上 |
| 关键词搜索 | `/x/web-interface/wbi/search/type?search_type=video&keyword=…&order=click` | play / duration / author / pic / pubdate |
| 单稿详情 | `/x/web-interface/view?bvid=…` | stat.* / duration / desc / pubdate |
| UP 资料 | `/x/relation/stat?vmid=…`、`/x/web-interface/card?mid=…` | follower / archive.count |
| UP 稿件列表 | `/x/space/arc/search?mid=…`（易限流，必要时用搜索代替） | 单条 play / length |

**能算出来的指标（这是选题的弹药）**

1. 播放量、弹幕数、回复数、收藏数、投币数、分享数
2. 弹幕率 = 弹幕 / 播放（「看得最不安静的」）
3. 互动率 = (回复 + 投币) / 播放（「最吵的」）
4. 收藏率 = 收藏 / 播放（「最值得存的」）
5. 投币率 = 投币 / 播放（「最值钱的」）
6. 时长 × 播放（「最短却最火的」）
7. 标题长度 / 关键词分布（「标题最像的 10 条」）
8. AI 相关占比（标题 +简介正则：AI|大模型|GPT|DeepSeek|机器人|生成）

## 3. 「之最」选题池（8 条，直接可用）

| # | 选题 | 算法 | 钩子（前 3 秒） |
|---|---|---|---|
| 1 | 收藏率最高的 10 条 | favorite/view 降序 | 「B 站有人存了一条视频，存了 13.6% 的播放量」 |
| 2 | 弹幕最吵的 10 条 | danmaku/view 降序 | 「一条视频，每 90 次播放就有 1 条弹幕」 |
| 3 | 最没人说话的爆款 | view 前 20 里 reply 最低 | 「468 万播放，只有 2 千条评论」 |
| 4 | AI 做的视频占了多少 | 热榜 100 条正则匹配 | 「热门 100 条里，12 条是 AI 做的」 |
| 5 | 最舍得投币的区 | 分区 coin/view | 「这个区的人，比别的区多投 3 倍币」 |
| 6 | 最短的爆款 | duration 升序 + view > 100 万 | 「13 秒，1317 万播放」 |
| 7 | 标题里出现最多的词 | 分词统计热榜标题 | 「热榜 100 条，有 23 条以『我』开头」 |
| 8 | 播放与评论最不成比例的 | reply/view 极值 | 「520 万播放，1.2 万评论，这两者不该同时出现」 |

## 4. 单集生产流程（6 步，约 3–4 小时）

1. **抓数（20 分钟）**：跑一个 `fetch_top.py`，把热榜 100 条 + 目标指标落成 `data.json`
2. **定题（10 分钟）**：从 §3 选题池挑一条，算出榜单，人工看一遍有没有「明显异常」（比如比赛视频刷榜）
3. **写稿（40 分钟）**：12–16 句，结构固定：结论前置 → 三个例子 → 一个反转 → 提问
4. **配音（20 分钟）**：Qwen3-TTS 单次合成 + 静音切句（与现有流程一致）
5. **渲染（60–90 分钟）**：用 §5 的四个组件拼 8–10 场
6. **封面 + 发布（30 分钟）**：16:9 与 4:3 两张，标题带数字

## 5. 视觉模板（全部复用现有组件）

- 每场必须 ≥2 物件（如：排行卡 + 条形对比）
