# 鲸鱼娘《打工日记》· 视频工作流

工作目录 `$W = ~/dsh-space/whale-video`。一集 60–90 秒。

## 0. 铁律

1. **配音冻结**：小紫 = Edge TTS `zh-CN-XiaoyiNeural`，rate `-2%`、pitch `+8Hz`（后处理见 §1）。不要再换音色、不要再改参数。
2. **规则必须先物件化**：本集要讲的任何规则/赛制/承诺，必须先变成一件**可截图的实物**（红头文件、合同、工牌、报告单、罚单），再写台词。写不出物件，就换选题。
3. **每场至少 2 个视觉物件，每 4–6 秒一次视觉更新**：不允许一场只有一个标题挂到底。
4. **每场第 0 帧必须"已结算"**：首帧就要有标题/卡片/数据，不能是动画起点。
5. **背景固定「深海夜光」**（§2.3），不用纯海洋蓝、不用大面积亮色底。
6. **彩色容器**，不许全用白框：每张卡片带色条或色头（红头/墨紫/薄荷/金）。
7. **版式变体不重复**：相邻两场不得同一版式。
8. **字幕 44px、单行、烧录**：白字四向深描边，宽 ≤1300px；超过就改台词，不许换行。
9. **音效 ≤5 个点音**（翻纸/印章/叮），禁止转场 whoosh、禁止错误 buzz、禁止弹入 pop。
10. 全片**无黑场**、无硬切（相邻帧差 >70 即硬切）。
11. **Day 数取最新一集**：HUD、台词、标题、发布包四处必须一致，改一次全改。
12. 发布必须带：AI 声明 + CC BY 音乐署名 + 非官方二创。

## 1. 配音（冻结，不再改）

**小紫的声音 = Edge TTS `zh-CN-XiaoyiNeural`（小伊 · 甜元气）**

- rate `-2%`，pitch `+8Hz`
- 后处理：`highshelf=f=6000:g=1.5` → `deesser=i=0.4` → `acompressor=threshold=-18dB:ratio=2` → `loudnorm=I=-16:TP=-1.5:LRA=9` → 48kHz
- 参考样音：`assets/xiaozi-voices/小紫试音-B-甜元气.mp3`
- 参数记录：`xiaozi-voice.json`（项目根）、`voice_preset_xiaozi.json`（本目录）

```bash
edge-tts --voice zh-CN-XiaoyiNeural --text "$(cat /tmp/text.txt)" \
  --rate=-2% --pitch=+8Hz --write-media /tmp/line.mp3
ffmpeg -y -i /tmp/line.mp3 -af "highshelf=f=6000:g=1.5,deesser=i=0.4,acompressor=threshold=-18dB:ratio=2:attack=8:release=180,loudnorm=I=-16:TP=-1.5:LRA=9,aresample=48000" -ac 2 -b:a 192k out.mp3
```

**冻结规则**：这是用户确认的最终音色，后续任何一集直接使用，不换引擎、不私自改 rate/pitch/后处理。

## 2. 视觉系统

**不变量（QA 会拦）**：安全区、最小间距、对比度 ≥4.5:1、首帧完整、相邻场不同版式、文字不溢出容器、无黑帧/硬切、字幕单行。

**可变部分**：每集从物件库里挑 6–10 个，组合成 8–12 个场景；每场 1 个主物件 + 1–3 个辅物件。底是深海夜光，道具是纸感亮块，两者搭配，不要整集一色。

### 2.1 规则物件化 · 五步法

1. **找规则**：这集要观众记住的一件事是什么？（赛制、KPI、期限、价格、承诺）
2. **找载体**：它在现实里对应哪张纸/哪个物？（HR 文件、合同、体检单、罚单、账单、工牌、票根）
3. **三秒可读**：物件上只留 3 行字——标题、最关键一条、一个红章。其余靠口播。
4. **一个数字**：物件必须带一个可验证的数字（30 天 / 5 项 / 60 分 / 0.53 元）。
5. **可截图**：物件单独截出来就能传播，不依赖上下文。

> 检验标准：把这一帧单独发给没看过的人，他能不能说出"这是什么规则、我输了会怎样"。

### 2.2 物件库（起点，不是清单）

**库是弹药，不是菜单。** 先看这一场要传什么信息，再从库里挑最贴合的一件；挑不到就**造新的**，造完回填。

选物件的判断顺序：

1. 这场的信息类型是什么——规则 / 数据 / 时间 / 对比 / 证据 / 情绪？
2. 观众会不会想截图？截下来能不能单独看懂？
3. 能不能 3 秒读完（≤3 行字 + 1 个数字 + 1 个章）？
4. 有没有现成的物件已经覆盖？覆盖度 <80% 就改，不要硬套。
5. 这个物件最近三集用过吗？用过就换一个，或换一个变体（换色/换表头/换角度）。

**每集自检**：至少 1 个新物件或新变体；不允许连续三集复用同一套卡片皮肤。

| 物件 | 长什么样 | 用于 | 动效 |
|---|---|---|---|
| **红头文件** | 顶部红色抬头条 + 文号 + 标题 + 正文 + 圆形公章 | 通知、赛制、处罚 | 纸张落下 + 盖章 |
| **合同/工牌** | 白卡 + 粗标题 + 条款 + 签名线 | 入职、规则、身份 | 滑入 + 签字 |
| **答题卡** | 两张大选项卡 + 选中标记 + 批改章 | 考问、对比、选择题 | 双卡错峰弹入 |
| **参考文献卡** | 标题 + 编号 + 状态标签（存在/查无此文） | 幻觉、证据、打假 | 逐张滑入 + 划掉 |
| **上下文进度条** | 深色面板 + 百分比 + 水位刻度 + 回收标记 | 记忆、容量、消耗 | 水位下降 |
| **监控画面** | REC 角标 + 时间码 + 16:9 画面 + 右下 NO SIGNAL | 摸鱼、偷拍、现场 | 时间码跳动 |
| **手机屏幕** | 真实 B 站画面 + 播放键 + 进度条 + 推荐标 | 刷视频、搜索、评论区 | 静帧 + 进度走 |
| **心率/体检图** | 米白卡 + 折线 + 结论词 + 加分数 | 身体、状态、情绪 | 折线画出 |
| **报告单** | 表头 + 5 行指标条 + 总分 + 印章 | 总评、盘点、成绩 | 逐行生长 |
| **印章** | 红/金/绿粗边框 + 大字 + 旋转 | 判定、盖章、结论 | 砸下 + 回弹 |
| **三选一投票卡** | A/B/C 三张 + 高亮轮播 + VOTE 标 | 互动、下期选题 | 依次弹入 + 循环高亮 |
| **工位图** | 四张桌子 + 灯 + 编号 | 竞争、团队、排位 | 逐个亮灯 |
| **账本/收据** | 窄纸条 + 虚线 + 合计行 | 花费、成本、收入 | 逐行打印 |
| **终端窗口** | 标题栏 + 命令行 + 光标 | 写代码、报错 | 打字机 |
| **新闻/热搜条** | 名次 + 标题 + 涨跌箭头 | 蹭热点、外部事件 | 逐行滑入 |
| **B 站三连** | 蓝/粉/金三个圆环图标 | 片尾转化 | 依次 spring |

完整规格（尺寸/色值/字号/动效参数）见 [`VISUAL-SYSTEM.md`](VISUAL-SYSTEM.md)。

**新增物件（造完必须回填）**

1. **命名**：中文名 + 英文组件名（如「罚单 · Ticket」）。
2. **定规格**：尺寸、底色、圆角、投影、字号、字重、旋转角、动效曲线（写进 `VISUAL-SYSTEM.md §3`）。
3. **定语义色**：一个物件一种含义色，不许一物多色。
4. **做组件**：在当期工程里新建参数化组件（写法可参考 `examples/checkup/src/ui.tsx`）。
5. **回填两处**：本表 +1 行、`VISUAL-SYSTEM.md §3` +1 节。
6. **验收**：单帧发给没看过的人，他能说出「这是什么规则、我输了会怎样」。

> 只允许「内容需要新物件」而去造，不允许「想用某个物件」而去改内容。

### 2.3 背景：深海夜光（固定）

| 层 | 参数 |
|---|---|
| 底色 | `linear-gradient(175deg, #0A1322 0%, #05080F 62%, #03060C 100%)` |
| 光柱 | 4 道，宽 360–540px，`blur(38px)`，`screen` 混合，透明度 0.16，缓慢摆动（±2.4°，±26px） |
| 焦散 | 3 团 620×300 椭圆，`rgba(120,180,255,0.13)`，`blur(20px)`，反向漂移 |
| 气泡 | 34 颗，半径 2–7px，上浮 8–26px/s，横向正弦漂移 12px |
| 鲸影 | 左下角，`#0E2A44`，透明度 0.16 |
| 暗角 | `inset 0 0 260px 90px rgba(0,0,0,0.62)` |
| 颗粒 | 点阵 `1px / 72px`，透明度 0.5（静态，不逐帧） |

**为什么不用海洋蓝**：纯海洋蓝（`#0E4166`）会把白纸道具洗灰、把紫发压暗、对比度掉到 4.5:1 以下。海洋感靠**光（光柱+焦散）和动（气泡+鲸影）**，不靠底色变蓝。

### 2.4 语义色（颜色要有含义，不是装饰）

| 含义 | 色 | 用法 |
|---|---|---|
| 信息/中性 | 蓝灰 `#7C8AA5` | 标题、说明 |
| 收入/正 | 绿 `#6ECD9F` | 赚到、达标、及格 |
| 亏损/负 | 珊瑚 `#E8604F` | 亏、翻车、不合格 |
| 承诺/强调 | 金 `#FFC53D` | KPI、军令状、加分 |
| 系统/警示 | 琥珀 `#E8A33D` | 报错、限流、幻觉 |

一屏里**语义色不超过 2 种**；颜色只跟随含义，不按页轮换。

### 2.5 人物：两套素材，别混用

| 套 | 素材 | 画幅 | 默认用途 |
|---|---|---|---|
| **半身成人** | `assets/emotes/` 20 张 | 1408×1408 | 正片特写、情绪细腻的段落 |
| **Q 版全身** | `assets/chibi/` 12 张（10 表情 + 2 换装） | 1536×2048 | 封面、片头片尾、轻喜剧、换装集 |
| **动作立绘** | `assets/actions-normal/`、`assets/actions-chibi/` 各 10 张 | 1536×2048 | 正在做一件事：讲解、挠头、叹气、冲刺、飞吻 |

规则：

1. **一集只用一套**，同屏不许混。
2. 正片默认半身；封面默认 Q 版全身（站姿完整、更好摆）。
3. 半身：每场一张、`right: -30`、`height: 980–1030`、浮动 9px。
4. Q 版：按可见区定位、脚底压出画框 10px；封面 16:9 用 `hr 1.35`，4:3 用 `1.22`（整张画布比，可见区只占 63%）。
5. 逐张用法：半身见 [`EMOTES.md`](EMOTES.md)，Q 版见 [`CHIBI.md`](CHIBI.md)，动作见 [`ACTIONS.md`](ACTIONS.md)。
6. 片尾三连图标（点赞/投币/收藏/关注）只能用 B 站 iconfont 字形，规范见 [`ICONS.md`](ICONS.md)。
7. **第三方模型角色（剧场配角）**：`assets/cast/portrait/`（半身 1536×2304）与 `assets/cast/chibi/`（全身 1024×1360）内有 Claude / ChatGPT / Grok / Qwen 四位。用于"被评估、被替代、派活、工位竞争"这类剧场互动，小紫仍是主角。用法见 [`CAST.md`](CAST.md)：一套一集、同屏最多 2 位、首次出现挂名字条、不贬低对手、不暗示官方合作。


### 2.6 字幕与安全区

- 位置：`top: 872px`，左起 30px，宽 1360px，居中；`font-size: 44px`，`font-weight: 800`，白字 + 四向深描边 + 底部渐变衬底。
- **必须单行**：> 26 字就删字，不要换行（换行会挡住人物）。
- 片头、片尾期间隐藏字幕与顶部栏。
- 正文内容底边 ≤ 860px；片尾三连区 500–700px。

## 3. 制作流水线

0. **写物件清单**：本集 8–12 场，每场列出「主物件 + 辅物件 + 一句话规则」——清单不过不写台词。
1. 写台词 `script_*.json`（口语、短句、一次反转、结尾可验证）。
2. 生成配音 → 按实测时长排 cue → 混音（`build_audio.py`）。
3. 写场景：每场一个版式；第 0 帧已结算；字幕自动跟 cue。
4. **设计审查**：`audit_ep.py` 必须 PASS。
5. **视频质检**：`qa_ep.py sample/xx.mp4` 必须 PASS。
6. 出封面 + 发布包 + 账本。

## 4. 设计审查门禁（不过 = 不许发）

`audit_ep.py` 逐场跑，任一项 FAIL 就退出码 1：

| 检查 | 门槛 |
|---|---|
| 文字两两重叠 | 0 |
| 文字是否在卡片内 | 必须在（±2px） |
| 内容进入字幕安全区 | 0（bottom ≤ 860） |
| 标题↔副标题间距 | ≥ 20 |
| 副标题↔内容间距 | ≥ 36 |
| 首帧文字块数量 | ≥ 4（首帧必须完整） |
| 文字对比度 | ≥ 4.5:1 |
| 相邻场景同版式 | 0 |
| 每场视觉物件数 | ≥ 2 |
| 最长无视觉更新时长 | ≤ 6s |
| 字幕行数 | = 1 |
| 音效点数 | ≤ 5 |

`qa_ep.py` 视频层：时长 58–92s、平均帧差 ≤6、硬切 0、闪烁 0、最小亮度 ≥20、首帧有内容、单帧亮度变化 ≤50。

## 5. 音效

全片只允许 5 类点音，合计 ≤5 次：

| 音 | 做法 | 电平 |
|---|---|---|
| 翻纸 | 白噪 + 低通 1.8kHz + 16 衰减 | −22 dBFS |
| 印章 | 58–84Hz 闷响 + 低通 520Hz + 13 衰减 | −20 dBFS |
| 叮 | 880Hz + 一次泛音 + 低通 2.6kHz | −24 dBFS |

**禁止**：转场 whoosh、错误 buzz、弹入 pop、连续音效叠字。BGM 固定 −16 LUFS 响度下的 0.15 增益，人声与 BGM 动态差保持 ~20dB。

## 6. 发布包

- 标题：`【鲸鱼娘打工日记 Day N】` / 番外 `【鲸鱼娘打工日记 · 番外】` + 一句"我出了什么事"
- 简介：身份 → 本集 3 件事 → 汇报承诺 → 账本 → 互动 → 合规三行
- 合规三行：AI 声明 / 非官方二创 / 音乐 CC BY 4.0 署名
- 标签：**`B站AI无限竞技场` 永远放第一位**（活动话题优先进流量池），其余按 `人工智能 AI vlog 鲸鱼娘 AI打工日记 DeepSeek 运营日记 二次元` 排；前三位仍决定分类倾向
- 时间 20:00–21:00，合集《鲸鱼娘的打工日记》
- 封面：按 `VISUAL-SYSTEM.md §9` 出，**一次出 16:9 与 4:3 两版**；深海底不变、双角标（小紫打工日记 + DAY N）、主标题阿里普惠体 115 Black + 白字珊瑚描边 + 发光 + 硬阴影，文字只留 3 块 + 1 个合规标

### 6.1 发布执行（catbus）

```bash
catbus bilibili item publish \
  --title "【鲸鱼娘打工日记 Day N】…" \
  --text @desc.txt \
  --video out/checkup.mp4 \
  --cover out/cover-16x9.jpg --cover43 out/cover-4x3.png \
  --tag 人工智能 --tag AI --tag 鲸鱼娘 --tag AI打工日记 \
  --category 231 --visibility public -y
```

- **`--cover` 是 16:9（播放页），`--cover43` 是 4:3（稿件列表页），两张必须同时给。** 少给一张，列表页就只能用系统裁切，构图会歪。
- `--category 231` = 科技 / 计算机技术，和系列已发稿件保持一致（不是 188 科技大区）。
- 只换封面不用重传视频：`catbus bilibili item edit <BV> --cover a16.jpg --cover43 a43.png`（提交后会重新审核）。
- 需要带 `--cover43` 的 catbus（对应提交 a4c2416 / PR #44）。npm 上的 0.2.1 还没有，本地分支构建即可，不必等合并：`git archive a4c2416 | tar -x -C /tmp/catbus-dual`，链上原仓库 node_modules 后 `npm run build`，用 `node dist/cli/main.js` 跑。
- 发布后检查：稿件列表页的缩略是不是 4:3 那张，不是就说明 `--cover43` 没生效。

### 主标题（白 / 冰蓝双色，2026-11-10 定稿）
